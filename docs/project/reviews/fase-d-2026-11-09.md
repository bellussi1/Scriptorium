# Fase D — model benchmark for the 8 GB GPU

Date: 2026-11-09

> **Superseded for model selection.** The 30-excerpt corpus was audited and
> replaced by the larger dev/test set in
> `docs/project/reviews/eval-corpus-2026-11-09.md`. This report remains the
> historical Fase D record and the source of the first smoke and first full
> matrix.

## Corpus

- 30 excerpts, 10 each from the official PT-BR editions of the Farseer trilogy
  (*O Aprendiz de Assassino*, *O Assassino do Rei*, *A Fúria do Assassino*),
  aligned paragraph-by-paragraph with the English originals.
- Alignment is monotonic and scored by shared proper nouns/numbers plus length
  ratio; low-confidence pairs are dropped. The corpus stays under
  `data/benchmark/literary/` (gitignored).
- Category mix: 7 introspection, 6 dialogue, 6 long syntax, 6 narration,
  5 description.
- Each row carries `reference_pt`, so the runner computes chrF in addition to
  the deterministic name/number/leakage/repetition metrics.
- No excerpt contains a digit, so `number_recall` is **n/a**, not zero. The
  harness now prints `n/a` instead of averaging an empty list to 0.0.

Builder: `scripts/build_aligned_corpus.py`.

## Harness

`scripts/benchmark_fase_d.py`:

- runs the installed models (`hy-mt2-7b`, `hy-mt2-7b-q6`, `index-translate-9b`,
  `qwen3-8b`);
- repeats each excerpt `--repeats` times (default 3);
- samples `nvidia-smi` memory/utilization once per second while the runner is
  active;
- aggregates chrF mean/σ, length ratio, name/number recall, leakage,
  repetition, latency p50/p95 and tokens/s;
- writes the blind review sheet and the separate A/B/C/D key;
- keeps all copyrighted outputs under `data/benchmark/` (gitignored).

Smoke command:

```bash
python scripts/benchmark_fase_d.py --models hy-mt2-7b --repeats 1 --limit 1
```

Full command:

```bash
python scripts/benchmark_fase_d.py --repeats 3
```

## Smoke result

One aligned excerpt, Hy-MT2 7B Q4:

- chrF **0.6496** against the official PT reference.
- name recall **1.0**, English leakage **0.0**, repetition **0.0106**.
- The output caught a real gender-agreement error: the official edition has
  “Hod estava ocupada”; the model produced “Hod estava ocupado”.
- Latency was **103 s** for one excerpt, not a valid speed measurement: the
  queue was translating *Fool's Errand* at the same time and the GPU was at
  ~97% utilization.

### Corpus correction

Two excerpts are misaligned and must be excluded from the headline chrF:
`royal-assassin-00` and `royal-assassin-03`. The alignment score accepted
paragraphs that share names but are different scenes. On the remaining 28
excerpts (84 rows per model):

| Model | chrF (clean) |
|---|---:|
| hy-mt2-7b | 0.6873 |
| hy-mt2-7b-q6 | 0.6800 |
| index-translate-9b | **0.7427** |
| qwen3-8b | 0.6830 |

Index-Translate 9B wins **26 of 28** excerpts on chrF; Hy-MT2 Q4 and Qwen3 win
one each. The rank is stable, but the absolute values still depend on the
alignment quality. The corpus needs a manual pass before it is used as a
permanent regression set.

## Qualitative reading

The blind sheet is `data/benchmark/fase-d/blind/blind_review.jsonl`; the label
key is `data/benchmark/fase-d/blind/blind_key.json` (A = Hy-MT2 Q4, B = Q6,
C = Index-Translate 9B, D = Qwen3 8B). Spot checks across dialogue,
description and long syntax found real differences that chrF does not capture:

- **Index-Translate 9B** has the best reference similarity, but shows a
  European-Portuguese bias: “as suas cores”, “Ela lembrava-me”, “Os seus olhos”.
  It also left `Buckkeep` untranslated in `assassins-quest-05`, where the
  glossary requires “Torre do Cervo”. It got the `Pretendente, Regal Farseer`
  phrase right, which the Hy-MT2 models did not.
- **Hy-MT2 Q4/Q6** read more naturally in Brazilian Portuguese and follow the
  glossary more consistently, but in `assassins-quest-05` both replaced
  “the Pretender, Regal Farseer” with “FitzChivalry Farseer”. That is a plot
  error, not a style preference.
- **Qwen3 8B** is the fastest and gets the long-syntax names right, but name
  recall is **0.8862** and the sample has agreement problems (“dos tabernas”,
  “a sua aparência”).
- **Hy-MT2 Q6** brings no quality gain over Q4 and is **2.6× slower** at p50;
  it is not a candidate for the 8 GB card unless a specific text benefits from
  the larger weights.

## Verdict

No model is a clean drop-in winner.

- **Production default stays Hy-MT2 7B Q4** for now: it is the fastest, reads
  as pt-BR and keeps the glossary, but it needs a name-substitution guard and
  the existing review gate.
- **Index-Translate 9B is the quality-first candidate**: best chrF on the clean
  subset, best per-excerpt win rate, and acceptable speed (p50 6.3 s). It should
  not replace Q4 until a pt-BR normalization pass and a per-occurrence glossary
  check exist, because the sample shows pt-PT forms and one untranslated
  `Buckkeep`.
- **Qwen3 8B** is not recommended for this pipeline: its speed is good, but
  name recall and agreement are worse.
- **Hy-MT2 Q6** is dropped from the local matrix: 2.6× slower, no measurable
  quality gain, and the larger weights squeeze the 8 GB card.

The blind sheet still needs a human/LLM rubric pass over all 120 entries before
any switch. chrF is a triage signal, not a verdict.

## Queue impact

**Pause now** stopped *Fool's Errand* at 94/851. The first resume attempt hit a
`disk I/O error` from a stale SQLite connection in the app container; restarting
the app fixed it. The persisted checkpoint held only 12 chunks, so the runner
resumed from the checkpoint (the queue showed 44/851 after the restart) and is
redoing the work that was not persisted. No translation was running during the
restart, and the job was resumed with the same `translation_id`
(`cli_e348a552`). The UI checkpoint can lag behind the live log while the
container writes through its WAL.
